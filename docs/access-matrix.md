# Матриця доступу ЛР04 — Incident, baseline 2-A

Рівень виконання: **добрий** («Добре»). Рядки відмінного рівня позначено «не виконувалось — рівень відмінний».

Ролі та ідентифікатор поточного користувача сервер бере лише з перевіреного principal
(`HttpContext.User`, claims `NameIdentifier` і `Role`, сформовані під час входу). Значення `role`,
`ownerUserId`, `status` чи інші поля з тіла запиту, URL, query або заголовків не є входом рішення.

Канонічне правило baseline 2-A: Reporter створює й редагує власний запис; Analyst читає інциденти
для аналізу й може перевести лише `New → Triaged`; Administrator має тільки прямо опубліковані
для цієї предметної області права — для Incident таких прав не опубліковано, тому він не має
автоматичного обходу ownership і діє як автентифікований користувач без власних інцидентів.

## Політика відмов (HTTP)

| Ситуація | Відповідь |
|---|---|
| Немає автентифікації (немає чинної cookie) | `401 Unauthorized`, Problem Details, без HTML redirect |
| Автентифікований користувач запитує чужий інцидент, який йому не видно (details, update, delete, triage, коментар) | `404 Not Found` — та сама відповідь, що й для неіснуючого id |
| Неіснуючий id | `404 Not Found` |
| Ресурс видимий, але дію заборонено (Analyst змінює/видаляє; Reporter чи Administrator виконує triage) | `403 Forbidden` |
| Дія дозволена, але поточний стан не допускає переходу (triage не з New) | `409 Conflict` |

**Обґрунтування 404 для чужого ресурсу.** Ідентифікатор інциденту сам по собі не має розкривати,
що такий запис існує й належить іншому користувачу. Тому для Reporter відповіді для чужого й
неіснуючого id нерозрізнювані: однаковий status, `Content-Type` і тіло Problem Details
(`title: "Інцидент не знайдено"`, без id у тексті); відрізняється лише поле кореляції `traceId`.
Обидві гілки використовують один helper. Політика однакова для details, update, delete, triage і
child endpoint.

**Коли 403.** Якщо суб'єкт уже бачить ресурс (Analyst читає будь-який інцидент; власник бачить
свій), приховувати його існування немає сенсу, тому заборонена дія над видимим ресурсом дає 403.

Привілейована дія `triage`: роль зчитується з principal; при відмові записується подія
`authorization.denied` (subject id, action, resource id, result, час сервера, той самий traceId,
що у відповіді) без cookie, пароля, токена й тіла запиту.

## Очікувані відповіді (зафіксовано до перевірок)

| Сценарій | Суб'єкт | Очікувано |
|---|---|---|
| Читання власного інциденту `…0001` | Alice (Reporter) | 200 OK |
| Читання інциденту Bob `…0002` | Alice (Reporter) | 404 Not Found |
| Читання неіснуючого інциденту | Alice (Reporter) | 404 Not Found, те саме тіло, що й для чужого (крім `traceId`) |
| Читання інциденту Alice та Bob | Morgan (Analyst) | 200 OK |
| Читання інциденту без входу | Анонім | 401 Unauthorized |
| Список інцидентів | Alice (Reporter) | 200 OK, лише `…0001`, `…0003`, `…0005` |
| Зміна назви інциденту Bob | Alice (Reporter) | 404 Not Found, дані Bob не змінилися |
| Видалення інциденту Bob | Alice (Reporter) | 404 Not Found, інцидент Bob лишився |
| Зміна власного інциденту з полями `role`, `status`, `ownerUserId` | Alice (Reporter) | 204 No Content; змінилися лише title і description |
| Зміна вмісту чужого інциденту | Morgan (Analyst) | 403 Forbidden, дані не змінилися |
| Triage власного інциденту в статусі New | Alice (Reporter) | 403 Forbidden, статус лишився New, подія `authorization.denied` |
| Triage інциденту Bob | Alice (Reporter) | 404 Not Found |
| Triage інциденту в статусі New | Morgan (Analyst) | 204 No Content, статус Triaged |
| Повторний triage того самого інциденту | Morgan (Analyst) | 409 Conflict |
| Triage будь-якого інциденту | Admin (Administrator) | 404 Not Found для невидимого (у seed адміністратор не має власних інцидентів) |
| Коментар `…0002` до інциденту Bob | Alice (Reporter) | 404 Not Found |
| Внутрішній коментар `…0003` до інциденту Alice | Alice (Reporter) | 404 Not Found; у details його немає |
| Внутрішній коментар `…0003` | Morgan (Analyst) | 200 OK |
| Будь-який захищений запит без входу | Анонім | 401 Unauthorized, без HTML redirect |
